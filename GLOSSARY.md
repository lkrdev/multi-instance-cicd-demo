# Glossary

- looker-cli
  - The Go CLI from [looker-open-source/looker-cli](https://github.com/looker-open-source/looker-cli) that replaces Gazer for folder, dashboard, and API automation.

- deploy ref
  - Looker Advanced Deploy API endpoint that deploys a specific Git commit SHA or version tag directly to production mode.

- dev mode
  - In the UI: sidebar toggle that isolates developer branch edits from production users.
  - In the API: authenticated sessions default to production; must be switched to dev mode via `PATCH /api/4.0/session` (`{"workspace_id": "dev"}`) before checking out branches or running validations.

- content validator
  - Looker API check that identifies broken Looks, dashboards, and tiles caused by LookML changes.

- sql validator
  - Explore query compiler that checks SQL dialect compatibility against warehouse connections before deployment.

- lookml test
  - Native `test:` block inside a model asserting query results and business logic in CI before merge.

- lams
  - LookML style linter from [looker-open-source/look-at-me-sideways](https://github.com/looker-open-source/look-at-me-sideways) checking naming conventions, primary keys, and descriptions.

- token file
  - Auth cache file (`~/.looker_auth`) generated by `looker-cli session login` and reused via `--token-file`.

- pdt pre-build
  - Building Persistent Derived Tables in dev mode during release to test DDL execution and warm cache tables before deploy.

- settings drift
  - Differences in instance settings, Labs flags, or legacy features between Stage and Prod.

- folder whitelist
  - YAML list of approved Shared folders to promote from Stage to Prod.

- board migration
  - Syncing Looker Boards and pinned tiles across instances by matching titles instead of internal IDs.

- udd
  - User-Defined Dashboard created through the Looker UI rather than in LookML.

- rollback tag
  - Previous release tag redeployed via the Advanced Deploy API to restore production without altering Git history.
